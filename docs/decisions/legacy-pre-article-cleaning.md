# 老式多 article 页面清洗

## 问题

部分老式网页会同时包含多个 `<article>`：前一个只是文章列表中的标题卡，后一个
才是正文，并可能使用 `<pre>` 保存长篇纯文本。旧清洗器直接返回第一个
`<article>`，导致 Cleaned HTML 只有标题而没有具体文章。

## 决策

- 删除脚本、样式和注释后，收集页面中所有 `<article>` 候选。
- 按可见文本量选择最充分的候选，不依赖特定网站域名或 CSS 类名。
- 没有 `<article>` 时依次尝试 `<main>`、常见正文 class 的 `<div>` 和
  `<body>` fallback。
- 对长度足够、包含多个自然语言段落的 `<pre>`，将空行分隔内容转换为段落，
  并识别 Setext 风格标题和简单列表，避免整篇文章使用等宽代码字体。
- 短 `<pre>`、包含 `<code>` 的块以及不符合自然语言启发式的内容仍按代码块
  保留。
- Markdown 先转换为 HTML 片段，再复用 Reader 的深色样式，避免
  `QTextDocument` 默认黑色文本覆盖主题。
- HTML 转 Markdown 时按实际尾随换行数量补齐段落分隔，保证相邻段落之间保留
  两个换行符，不会在 Markdown 渲染时合并成一段。
- 测试使用本地 UTF-8 fixture，不依赖真实网站或网络。

## 本地缓存处理

算法修复不会删除原始 HTML。对于已经保存了旧错误清洗结果的文章，可以直接从
本地 `original_html` 强制重新生成 Cleaned HTML 和 Markdown，无需再次联网。
