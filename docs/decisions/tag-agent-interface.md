# Tag Agent 接口决策

## 目标

Tag Agent 是手动标签的可选增强：用户主动请求后，统一 LLM Provider 根据
当前文章生成少量标签建议；建议本身不修改任何本地数据，只有用户明确选择并
点击“应用所选”后，才通过既有 `TagService` 创建和关联标签。

## 分层边界

- `TagAgent` 只负责构造 Provider 请求、解析建议和返回安全错误，不访问
  SQLite，也不调用标签写入接口。
- `TagSuggestionPanel` 只负责后台生成、展示、勾选、放弃和确认交互。
- `MainWindow` 在用户确认后将标签名称交给既有手动标签流程。
- 未配置 Tag Agent 时，手动创建、关联、重命名、删除和筛选标签保持可用。

## Provider 与 Prompt

- 复用 Summary/Translation 使用的统一 `LLMProvider` 协议，但使用 Tag
  Agent 自己的本地 Provider 配置 profile。
- 不写死厂商、模型、Base URL 或 API Key。
- 支持自定义 Prompt，但强制输出约束始终要求只返回 JSON 标签数组。
- 请求包含文章标题、优先级最高的可读正文、已有本地标签和当前已分配标签。
- 文章内容只在用户点击“生成建议”后发送给已配置的 Provider。

## 建议解析与安全限制

- 优先解析 JSON 数组，也兼容带 `tags` 数组的对象及简单逐行文本。
- 标签会去除项目符号、合并空白、按大小写去重，并遵守 64 字符上限。
- 当前文章已经拥有的标签不会再次显示为建议。
- 一次最多返回 8 个建议，界面默认请求 5 个。
- Provider 未配置、调用失败或无可用建议时只显示可翻译错误，不影响阅读和
  手动标签。

## 用户确认

- 建议生成后默认勾选，但不会自动写入。
- 用户可取消任意建议，也可以放弃整组建议。
- 只有“应用所选”触发本地标签写入；切换文章会清除旧文章建议并忽略过期的
  后台结果。
- 应用建议复用手动标签的幂等创建机制，不引入新的标签存储表。

## 验证

- `tests/test_tag_agent.py` 使用 `MockLLMProvider` 验证 Prompt、解析、去重、
  Provider 失败、自定义 Prompt、后台界面和确认后写入。
- 测试不依赖真实网络、真实 API Key 或在线 LLM。
