# 手动标签接口决策

## 目标

第四阶段的标签功能用于本地整理文章。它必须在没有账号、云同步、API Key
或 AI Provider 的情况下完整可用；Tag Agent 不属于本次实现范围。

## 分层边界

- `TagService` 是 UI 使用的唯一标签业务边界，负责标签增删改查、文章绑定和
  组合筛选。
- `BackendArticleService` 将该边界适配到 SQLite；UI 不直接执行 SQL。
- `MockArticleService` 提供相同行为，供离线自动测试和独立界面验证使用。
- 标签名称会合并多余空白、拒绝空名称并限制为 64 个字符；同名比较不区分
  大小写，重复创建返回已有标签。

## 本地数据

- `tags` 保存标签名称。
- `article_tags` 保存文章与标签的多对多关系，并使用联合主键避免重复绑定。
- 删除文章或标签时只级联删除相应绑定；删除标签不会删除文章。
- Feed 删除所触发的文章级联删除也会清理无效绑定。

## 交互

- Reader 标签浮层只编辑当前文章：可输入一个或多个逗号分隔标签，也可通过
  可选标签按钮添加或移除已有标签。
- 侧栏 Tags 页面显示标签及文章数量。勾选多个标签时，只显示同时拥有全部
  所选标签的文章。
- 标签可通过侧栏右键菜单重命名或删除；删除前必须经过明确确认。
- 标签筛选是跨订阅源的全局集合。清除筛选后返回用户原先选择的全部文章、
  星标或具体 Feed 集合。

## 失败策略

任何标签读写失败都只显示可翻译的本地错误提示，并保留 Reader 基础阅读。
标签功能不产生网络请求，也不调用 LLM Provider。

## 验证

- `tests/test_tags.py` 使用内存或临时 SQLite 数据库验证迁移、持久化、幂等
  创建、关联计数、重命名冲突、级联清理和多标签组合筛选。
- 同一测试文件使用 Qt offscreen 平台验证 Reader 标签浮层、侧栏组合筛选和
  主窗口接线，不依赖真实网络或在线 LLM。
