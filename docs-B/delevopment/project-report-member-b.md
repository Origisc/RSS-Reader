# Mercury RSS Reader 项目汇报

## 1. 项目简介

Mercury 是一款使用 Python 3.13 和 PySide6 开发的桌面 RSS 阅读器。

项目以“本地优先、隐私优先、跨平台、AI 可选”为核心原则，在完成订阅、
阅读和内容整理等基础功能的同时，通过统一的 LLM Provider 接口提供文章摘要
与逐段翻译能力。

Mercury 不要求用户注册或登录。订阅源、文章缓存、阅读状态、AI 配置、
摘要、翻译、星标和标签默认保存在本地 SQLite 数据库中。

---

## 2. 项目目标

- 建立完整的 RSS 阅读闭环。
- 改善网页文章的阅读体验。
- 在不依赖 AI 的前提下保证基础阅读功能可用。
- 提供厂商中立、用户主动配置的 AI 能力。
- 支持文章收藏、标签和筛选。
- 保持模块之间低耦合，便于继续扩展和测试。

## 3. 已实现功能

### 3.1 RSS 阅读与订阅管理

- 添加 RSS Feed。
- 通过 OPML 批量导入订阅源。
- 刷新订阅并获取文章。
- 使用订阅源、文章列表和 Reader 组成三栏式主界面。
- 查看文章标题、来源、时间和正文。
- 支持文章已读、未读状态及“仅未读”筛选。
- 提供独立的“多选删除”按钮，进入模式后无需按 `Ctrl` 或 `Shift`，
  可以直接点击任意、不连续的 Feed 进行选择或取消。
- 删除按钮实时显示已选择的 Feed 数量，并提供退出多选模式的取消按钮。
- 批量删除前显示所选数量和完整 Feed 名单。
- “全部文章”和“星标”等虚拟入口不会成为删除目标。
- 删除 Feed 时在同一事务中同步清理相关本地缓存文章。
- 批量删除任一目标失效时整批回滚，不会只删除一部分。
- 订阅源、文章和阅读状态保存到本地数据库，重启应用后仍可恢复。

### 3.2 Reader 阅读体验

- 支持原始内容、Cleaned HTML 和 Markdown 三种视图。
- 抓取文章网页正文。
- 清理广告、导航和脚本等无关内容。
- 保留标题、链接、图片、列表、表格和代码块等重要结构。
- 图片异步加载，减少加载过程中对界面的阻塞。
- 抓取或清洗失败时回退到 Feed 原文，保证文章仍然可读。
- 支持调整字体大小、行高和内容宽度。
- 支持浅色和深色主题。
- 支持简体中文和英文界面即时切换，无需重新启动。
- 提供快捷键帮助页面。

### 3.3 AI Provider

- 建立统一的 `LLMProvider` 抽象。
- 支持配置 Base URL、模型名称、API Key 和请求超时。
- 提供 Provider 连接测试。
- 兼容标准 Chat Completions 接口。
- 业务逻辑不写死任何单一 LLM 厂商。
- 只有用户主动生成摘要或翻译时才发送文章内容。
- 未配置 Provider 或调用失败时，基础阅读功能仍然正常。
- API Key 不进入日志、状态栏或错误提示。

### 3.4 Summary Agent

- 支持简体中文、英文和与原文相同三种摘要语言。
- 支持简略、标准和详细三种摘要程度。
- 支持自定义 Prompt。
- 自定义 Prompt 负责控制摘要结构和侧重点，不能覆盖用户选择的摘要语言。
- Provider 返回错误语言时，自动进入专用语言校正流程。
- 语言校正阶段移除自定义 Prompt 的干扰，最多执行三次 Provider 调用。
- 摘要异步生成，不阻塞文章阅读。
- 支持重新生成并显示生成时间。
- 摘要结果保存在本地，重启后可以恢复。
- 摘要失败时不会隐藏或破坏文章正文。

### 3.5 Translation Agent

- 支持选择目标语言和填写自定义 Prompt。
- 长文章自动分段处理。
- 保留文章段落顺序。
- 在 Reader 中按照“一段原文、一段译文”的形式逐段对照显示。
- 翻译过程中渐进显示已完成的段落。
- 支持原文与双语对照视图切换。
- 支持重新翻译。
- 保留 Markdown 中的链接、图片及其他重要结构。
- 检测明显的错误语言和内容遗漏，并自动纠正重试。
- 单段失败不会中断后续段落，失败段落仍然保留原文。
- 结构化翻译结果保存在本地，重启后可以恢复。

### 3.6 星标收藏

- 在文章列表中为文章添加或取消星标。
- 已星标文章显示黄色实心星。
- 点击星标不会改变当前文章选择。
- 侧栏提供全局星标入口和星标数量。
- 星标列表可以与“仅未读”组合筛选。
- 在星标列表取消星标后，自动接续选择下一篇或上一篇文章。
- 自动接续选择不会误将新文章标记为已读。
- 星标状态保存在本地，重启和刷新 Feed 后仍然保留。

### 3.7 手动标签与筛选

- 创建标签。
- 给文章添加或移除标签。
- 重命名标签。
- 删除标签前显示确认对话框。
- 删除标签不会删除文章。
- 支持按照标签筛选文章。
- 多标签筛选采用“同时包含全部所选标签”的组合语义。
- 标签和文章之间的关系保存在本地。
- 标签功能不依赖 AI。

## 4. 技术架构

项目采用分层结构：

```text
PySide6 UI
    ↓
Service 接口
    ↓
业务工作流 / Agent
    ↓
本地 SQLite / LLM Provider
```

各层职责如下：

- UI 层负责展示、用户交互和异步任务状态。
- Service 层负责为 UI 提供稳定的数据接口。
- Agent 层负责摘要和翻译工作流。
- Provider 层负责统一不同 LLM 服务的调用方式。
- Storage 层负责本地数据持久化。

这种架构使 UI 不需要直接执行 SQL 或发送 LLM 请求，也可以使用 Mock
Service 和 Mock Provider 独立测试。

## 7. 当前存在的问题

### 7.1 图片之间的间隔过大

#### 问题表现

部分文章包含连续图片时，Reader 中图片之间会出现过大的垂直空白，导致正文
不够紧凑，需要频繁滚动。

#### 可能原因

- 原始 HTML 中图片外层包含空段落或多余换行。
- Cleaned HTML 保留了图片容器原有的 margin。
- Reader 样式同时对段落、图片和图片容器设置了间距。
- 图片异步替换后仍保留占位元素的高度或空白节点。

#### 后续优化方向

- 清理只包含图片或空白内容的多余段落。
- 分别设置正文段落和图片容器的 CSS 间距。
- 对连续图片使用更紧凑的展示规则。
- 增加包含连续图片的本地 HTML fixture 和视觉回归测试。

### 7.2 摘要和翻译速度偏慢

#### 问题表现

- 长文章翻译需要执行多次分段请求，整体等待时间较长。
- 摘要发生语言错误时，需要额外执行语言校正请求。
- 使用本地小型模型或响应较慢的在线 Provider 时，等待更加明显。

#### 可能原因

- 长文章分段后请求数量较多。
- 当前翻译流程为了保证顺序和完整性，整体并发较保守。
- 错误语言、内容遗漏等情况会触发纠正重试。
- Provider 网络延迟、模型推理速度和用户设备性能存在差异。

#### 后续优化方向

- 优化文章分段大小和段落合并策略，减少不必要的请求。
- 在保证段落顺序和 Provider 限流安全的前提下，引入有限并发。
- 继续使用渐进式显示，让用户先看到已经完成的段落。
- 对相同文章、配置和 Prompt 复用本地缓存结果。
- 增加取消任务、进度显示和预计剩余段落数量。
- 调研流式响应，使摘要和翻译内容能够更早显示。

## 8. 后续计划

### 8.1 Tag Agent

计划在现有手动标签系统上增加 AI 标签建议。

预期功能：

- 复用现有统一 LLM Provider。
- 支持自定义 Tag Prompt。
- 根据文章内容生成标签建议。
- 显示建议标签及生成状态。
- 用户确认后才把建议应用到文章。
- 用户可以修改或拒绝建议。
- AI 失败时不影响手动标签功能。
- 不允许 Agent 未经确认批量修改文章标签。

Tag Agent 是手动标签功能的增强，而不是标签系统的必要依赖。

### 8.2 文章导出

计划增加文章内容的本地导出功能。

预期功能：

- 导出原始内容、Cleaned HTML 或 Markdown。
- 可选包含文章标题、来源、链接和发布时间。
- 可选包含摘要和双语翻译结果。
- 优先支持 UTF-8 Markdown 和 HTML。
- 后续根据需求增加 PDF 等格式。
- 文件名需要处理 Windows、Linux 和 macOS 的非法字符。
- 导出失败时不能影响本地文章和缓存。
- 导出过程只写入用户选择的本地路径，不上传文章内容。

## 9. 后续开发优先级

建议按照以下顺序推进：

1. 修复图片间隔过大的 Reader 展示问题。
2. 优化摘要与翻译的任务进度和响应速度。
3. 实现 Markdown / HTML 文章导出。
4. 在手动标签稳定的基础上实现 Tag Agent。

优先解决阅读体验和性能问题，再增加新的功能，可以降低后续功能与现有问题
相互影响的风险。

## 11. 汇报总结

Mercury 已经完成了从基础 RSS 阅读器到本地智能阅读工具的主要演进。

当前版本不仅可以完成订阅、刷新、阅读和本地缓存，还支持正文清洗、
Markdown 转换、阅读样式、中英文界面、AI 摘要、逐段双语翻译、星标收藏和
手动标签。AI 功能通过统一 Provider 接入，不会成为基础阅读功能的依赖。

下一阶段将重点解决图片间隔过大和摘要、翻译速度偏慢的问题，并逐步实现多选
删除、文章导出和 Tag Agent。在继续增加智能功能的同时，项目仍会坚持本地
优先、用户确认、失败可回退和可独立测试的设计原则。
